# Tend v0.1 Walking Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One local web page that lists every Tend-started Claude Code session, shows its hook-driven state, streams its live terminal, and notifies when a session needs you.

**Architecture:** A single Node process (`bin/tend.mjs`) runs an HTTP server on 127.0.0.1. Sessions run `claude` inside a private tmux server (`tmux -L tend`). Hook events arrive by HTTP POST, are stored in SQLite (`node:sqlite`) and folded by a pure state machine. State changes go to the browser over SSE. The terminal streams through tmux control mode (snapshot + `%output` bytes over SSE, keys via `send-keys -H`). The UI is plain ES modules plus a vendored xterm.js.

**Tech Stack:** Node 26 (native TypeScript type-stripping, `node:test`, `node:sqlite`), TypeScript 5 (typecheck only), tmux 3.x, `@xterm/xterm` 5.5.0 + `@xterm/addon-fit` 0.10.0 (browser), `@xterm/headless` 5.5.0 (tests only). No native addons, no web framework.

**Spec:** `docs/design/2026-10-27-tend-design.md` (Phase 0 overrides at its top), `docs/research/phase-0/RESULTS.md`, scope from `docs/versions/v0.1/GO-NO-GO.md`.

## Global Constraints
- Bind `127.0.0.1` only. Default port `4977` (`TEND_PORT` overrides). Data dir `~/.tend` (`TEND_HOME` overrides).
- Token: 32 random bytes hex, stored at `<TEND_HOME>/token` with mode `0600`, **stable across restarts**. Accepted via header `x-tend-token`, cookie `tend_token`, or query `key` (the query sets the cookie). `GET /health` is the only unauthenticated route.
- Reject requests whose `Origin` (if present) isn't `http://127.0.0.1:<port>` or `http://localhost:<port>`, and whose `Host` isn't `127.0.0.1:<port>` or `localhost:<port>` → `403`.
- tmux socket name `tend` (`TEND_TMUX_SOCKET` overrides, used by tests). Set `window-size manual` on server start.
- Claude binary: `claude` on PATH (`TEND_CLAUDE_BIN` overrides; tests use `test/fake-claude.mjs`). Launch: `<bin> --settings <TEND_HOME>/sessions/<id>/settings.json`. **Never** pass `--dangerously-skip-permissions`. Don't change the user's permission mode.
- All subprocesses via `execFile`/`spawn` with argument arrays, never a shell string.
- Hook events subscribed in v0.1: `UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, Notification, Stop, SubagentStop, SessionEnd`. All are `type: "http"` to `http://127.0.0.1:<port>/hook`, with headers `x-tend-token: <token>` and `x-tend-session: <tend session id>`, timeout `10`. **v0.1 never holds a PermissionRequest:** it answers `{}` immediately so Claude shows its own dialog.
- No file over 600 lines. Only dependencies: `@xterm/xterm`, `@xterm/addon-fit` (runtime, served to the browser); `typescript`, `@types/node`, `@xterm/headless` (dev).
- Source files use only erasable TypeScript (no `enum`, no parameter properties, no namespaces) so `node` runs them directly. Imports use explicit `.ts` extensions. **Type-only imports must use `import type`** (enforced by `verbatimModuleSyntax` + `erasableSyntaxOnly` in tsconfig).
- Every tmux call passes `-f /dev/null -L <socket>` so the user's `~/.tmux.conf` can't change behaviour.
- Session ids are validated against `^[0-9a-f]{8}$` (route `:id` and the `x-tend-session` header) before any file path or tmux use. Invalid ids → `404` (routes) / `202` ignored (hook).
- Static files are served from a fixed lookup map (URL → absolute file), never by joining request paths. Request bodies are capped: `/keys` 64 KB, JSON bodies 16 KB → `413`.
- UI copy follows the brand voice: lowercase wordmark `tend.`, states read "Working", "Needs you", "Idle", "Ended". No exclamation marks.

## Review Focus
1. **`tmux` or `claude` missing:** `node bin/tend.mjs` exits with a one-line fix ("tmux not found: brew install tmux"), not a stack trace. Test in Task 12.
2. **Folder paths with spaces or shell metacharacters** (`~/My Projects/a;b`) start a session correctly, and a non-existent folder returns `400 {"error":"Folder not found: …"}`. Test in Task 8.
3. **Hook POST with a wrong token or unknown `x-tend-session`:** `401` / `202` ignored, never a crash or a phantom session. Test in Task 8.
4. **A multi-byte UTF-8 character split across two `%output` lines,** and output bursts over 64 KB, render without mojibake. Test in Task 5.
5. **The browser reconnecting the terminal stream 20 times** leaves exactly one tmux control-mode client per session (reference-counted, closed after the last viewer leaves). Test in Task 9.

### Task 3: Pure state machine and notification decision

**Files:**
- Create: `src/state.ts`, `test/unit/state.test.ts`

**Interfaces:**
- Consumes: `TendEvent` (Task 2)
- Produces:
  - `type Need = 'permission' | 'question' | 'plan'`
  - `type SessionState = { status: 'starting' | 'working' | 'needs_you' | 'idle' | 'ended'; need?: Need; since: number; lastTool?: string }`
  - `initialState(now: number): SessionState`
  - `reduce(s: SessionState, e: TendEvent): SessionState`
  - `type NotifyIntent = { sessionId: string; title: string; body: string }`
  - `notifyFor(prev: SessionState, next: SessionState, sessionId: string, sessionName: string): NotifyIntent | null`
- Rules (from spike evidence):
  - `UserPromptSubmit | PreToolUse | PostToolUse | PostToolUseFailure` → `working`, clearing `need`. Exception: `PreToolUse` for `AskUserQuestion`/`ExitPlanMode` doesn't clear an existing need.
  - `PermissionRequest` → `needs_you` with need = `question` if tool is `AskUserQuestion`, `plan` if `ExitPlanMode`, otherwise `permission`.
  - `Notification` and `SubagentStop` → **no change**.
  - `Stop` → `idle`.
  - `SessionEnd | pane_exit` → `ended`, which is terminal (later events are ignored).
  - `since` updates only when `status` or `need` changes.
  - `lastTool` = tool of the latest `PreToolUse`.
- `notifyFor` returns an intent only when `next.status==='needs_you'` and (`prev.status!=='needs_you'` or `prev.need!==next.need`). Title is `"<sessionName> needs you"`. Body is `"Wants permission: <lastTool>"` / `"Has a question"` / `"Plan ready for approval"`.

  - The sequence `PermissionRequest(Write)`, `Notification`, `PostToolUse`, `Stop`, `SubagentStop` ends in `idle`, and exactly **one** non-null `notifyFor` across the transitions.
  - `SessionEnd` then `PreToolUse` stays `ended`.
  - **Property test** (500 random sequences over all kinds, seeded PRNG): `need` is set iff `status==='needs_you'`; `ended` is absorbing; the count of intents ≤ the count of `PermissionRequest` events.

### Task 5: tmux adapter and control-mode decoder

**Files:**
- Create: `src/tmux.ts`, `src/control-mode.ts`, `test/unit/control-mode.test.ts`, `test/integration/tmux.test.ts`, `test/helpers.ts`

**Interfaces:**
- Produces:

    - `available(): boolean`
    - `ensureServerOptions(): void` (sets `window-size manual` once a server exists)
    - `newSession(name: string, cwd: string, argv: string[], cols: number, rows: number, env: Record<string,string>): void`
    - `list(): string[]`
    - `has(name: string): boolean`
    - `paneDead(name: string): boolean`
    - `kill(name: string): void`
    - `resize(name: string, cols: number, rows: number): void`
    - `snapshot(name: string): Buffer` (bytes = `ESC[2J ESC[H` + `capture-pane -p -e` joined with `\r\n` + cursor move to `#{cursor_y}+1;#{cursor_x}+1`)
  - `control-mode.ts`:
    - `decodeOutput(line: string): { pane: string; bytes: Buffer } | null`
    - `class ControlClient` with `constructor(socket: string, session: string)`, `onBytes(fn: (b: Buffer) => void): () => void`, `sendKeys(data: Buffer): void` (writes `send-keys -t <session> -H <hex…>`), `close(): void`
  - `helpers.ts`: `tempHome(): string`, `uniqueSocket(): string`, `killSocket(socket: string): void`
- `newSession` issues **one chained invocation**, so options exist before the process can exit (verified on tmux 3.8):
  `tmux -f /dev/null -L <socket> start-server ; set -g remain-on-exit on ; set -g window-size manual ; new-session -d -s <name> -x <cols> -y <rows> -c <cwd> -e K=V … <argv…>`
  Pass `;` as separate array elements. `ensureServerOptions()` re-applies the two options for an already-running server, and is a no-op if none exists.
- `ControlClient` attaches with `-C attach -t <session>`. Because `window-size manual` is set, it does **not** send `refresh-client -C`; size is controlled only by `Tmux.resize`.
- The decoder reads control-mode stdout as `latin1` and turns `\ooo` octal escapes into bytes. Every other char code is pushed as its byte (`& 0xff`). (Spike bug: never re-encode as UTF-8.)
